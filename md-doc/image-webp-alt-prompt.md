# Image WebP Alt Prompt

이 문서는 사용자가 준비한 이미지를 허브 MDX 본문에 넣을 때만 사용하는 이미지 삽입 전용 실행 문서다.
글 작성, SEO, frontmatter, 내부 링크, related panel, 품질 게이트의 전체 기준은 `md-doc/post-codex-command.md`를 따른다.
이미지 변환, 경로, 삽입 위치, alt, 원본 처리, 최종 검증은 이 문서를 단일 원본으로 본다.

실제 작업 흐름:
- Codex는 먼저 이미지 없이 KO/EN 본문을 작성한다.
- 사용자는 작성된 본문을 Gemini Gems에 넣어 이미지 프롬프트, 파일명, alt, 캡션 후보를 만든다.
- 사용자는 그 결과를 바탕으로 이미지를 직접 준비하고 파일명/alt를 정리한 뒤 Codex에 이미지 삽입을 요청한다.
- Codex는 Gemini 결과물을 그대로 확정값으로 보지 않고, 이 문서 기준으로 파일명, 경로, `.webp`, KO/EN alt, 중복 여부를 다시 검수한 뒤 MDX에 삽입한다.

---

## 1. 적용 범위

[DO]
- 사용자가 이미지 파일을 직접 준비한 뒤 삽입을 요청했을 때 이 문서를 따른다.
- Gemini Gems 등 외부 도구가 만든 파일명, alt, 캡션은 삽입 전 검수 대상 입력값으로만 본다.
- 게시용 이미지는 `.webp`로 통일한다.
- MDX 본문에는 `/images/...webp` 경로만 남긴다.
- alt는 접근성과 검색 맥락을 함께 고려해 짧고 구체적으로 보정한다.
- 이미지 삽입 후 실제 파일 존재, 경로, alt, 중복 여부를 검증한다.
- 이 문서로 처리하는 기본 작업 범위는 이미지 파일 처리, 이미지 마크업 삽입, alt 보정, 경로 검증으로 제한한다.

[NOT]
- 글 작성 단계에서 Codex가 임의로 본문 이미지 마크업을 넣지 않는다.
- 기존 저장소 이미지나 이전 포스팅 이미지를 새 글에 재사용하지 않는다.
- 이미지가 준비되지 않았는데 깨진 `/images/...` 경로를 MDX에 먼저 넣지 않는다.
- 이미지 생성 프롬프트 자체를 이 문서에서 새로 만들지 않는다.
- Gemini가 만든 캡션, OG 이미지, 썸네일 제안을 별도 요청 없이 MDX나 metadata에 자동 반영하지 않는다.
- 이미지 삽입 요청만 받은 경우 본문 문단, H2/H3, Quick Summary, Related panel, CTA, 내부 링크 문구를 수정하지 않는다.

## 2. 작업 전 입력 확인

작업 전에 아래 정보를 확인한다.

- 대상 slug 또는 URL
- KO/EN 중 어느 파일에 넣을지, 또는 KO/EN 둘 다 넣을지
- 이미지 원본 파일 경로
- 파일명 suffix: KO는 `-kr`, EN은 `-en`
- 삽입 위치: H2 제목, 문단 위치, 또는 기존 placeholder
- 사용자가 준 alt가 있는지
- Gemini 결과물이 있다면 파일명, alt, 캡션, 썸네일/OG 추천 여부
- 사용자가 캡션 또는 OG 이미지까지 실제 반영하라고 요청했는지

기본값:
- KO/EN 이미지가 함께 주어지면 KO 파일과 EN 파일을 함께 확인한다.
- `-kr` 이미지는 KO MDX에, `-en` 이미지는 EN MDX에 넣는다.
- 삽입 위치가 없으면 관련 H2 바로 아래 또는 해당 설명 문단 직후를 우선 검토한다.
- 캡션은 기본적으로 MDX에 넣지 않는다.
- OG 이미지 또는 썸네일 metadata는 사용자가 명시적으로 요청한 경우에만 검토한다.

## 2-A. Gemini 결과물 처리 규칙

Gemini Gems가 만든 출력은 초안이다. 아래 항목을 다시 확인한 뒤에만 파일명 또는 alt로 사용한다.

[DO]
- slug가 실제 글 slug와 일치하는지 확인한다.
- `/images/hub/[slug]/` 경로가 실제 게시 경로와 맞는지 확인한다.
- 파일명이 lowercase, hyphen separator, `.webp` 확장자 형식인지 확인한다.
- KO 파일명은 `-kr.webp`, EN 파일명은 `-en.webp`로 끝나게 보정한다.
- KO alt와 EN alt가 서로 섞이지 않았는지 확인한다.
- alt가 제목/H2 복붙이나 키워드 나열이면 실제 장면 설명으로 보정한다.
- 같은 글 안에서 alt 문장 구조가 반복되면 서로 다른 장면 기준으로 바꾼다.
- Gemini가 추천한 이미지 수가 너무 많으면 본문 이해와 이미지 검색 유입에 도움 되는 3~5개만 우선 검토한다.

[NOT]
- Gemini가 만든 파일명에 `.webp`가 없는데 그대로 쓰지 않는다.
- `-kr`, `-en` suffix가 없는 파일명을 그대로 쓰지 않는다.
- Gemini가 만든 `/images/...` 경로를 실제 파일 존재 확인 없이 MDX에 넣지 않는다.
- 캡션을 본문에 자동 삽입하지 않는다.
- OG 이미지 또는 썸네일 추천을 metadata에 자동 반영하지 않는다.
- 실제 아이돌, 그룹명, 브랜드 로고, 앨범 커버, 저작권 포스터가 중심인 이미지 프롬프트 결과물을 그대로 쓰지 않는다.

## 3. 파일 경로와 이름 규칙

저장 위치:

```text
public/images/hub/[hub-slug]/
```

MDX 본문 경로:

```text
/images/hub/[hub-slug]/[file-name-kr.webp]
/images/hub/[hub-slug]/[file-name-en.webp]
```

규칙:
- 게시 폴더는 항상 `public/images/...` 아래에 둔다.
- MDX에는 `public`을 쓰지 않고 `/images/...`로 시작하는 경로만 쓴다.
- 최종 게시본은 항상 `.webp`다.
- KO 파일 이미지는 `-kr.webp`, EN 파일 이미지는 `-en.webp`로 끝낸다.
- 원본 확장자가 `png`, `jpg`, `jpeg`여도 MDX에는 원본 확장자를 남기지 않는다.
- 사용자가 `/images/...` 경로만 준 경우에도 대응하는 `public/images/...` 실파일을 확인한다.
- Gemini 파일명이 확장자 없이 `image-name-1-kr` 형식이면 게시 파일명은 `image-name-1-kr.webp`로 확정한다.
- Gemini 파일명이 `-kr`/`-en` 없이 끝나면 KO/EN 용도를 확인한 뒤 suffix를 붙인다.

---

## 4. 변환 규칙

1. MDX를 수정하기 전에 원본 파일이 실제로 있는지 확인한다.
2. 원본 확장자가 `png`, `jpg`, `jpeg`이면 `.webp`로 변환한다.
3. 원본이 이미 `.webp`라면 게시 폴더 위치와 파일명 suffix만 확인한다.
4. `.webp` 파일이 실제로 생성되거나 존재하는 것을 확인한 뒤에만 MDX를 수정한다.
5. 변환 후에는 MDX 참조 경로와 실제 파일 경로가 정확히 대응하는지 확인한다.

금지:
- `MDX 먼저 수정 -> 파일은 나중에 확인` 순서 금지
- 존재하지 않는 `.webp` 경로 삽입 금지
- 원본 파일명과 게시 파일명이 뒤섞인 상태로 보고 금지

---

## 5. 원본 파일 처리

기본값:
- 원본 파일은 삭제하지 않는다.

삭제 가능한 경우:
- 사용자가 명시적으로 원본 삭제를 요청한 경우
- `.webp` 변환이 끝났고, MDX가 `.webp`만 참조하며, 사용자가 원본 보관이 필요 없다고 확인한 경우

삭제 전 확인:
- `MDX 참조 경로 == 실제 생성된 .webp 경로`
- `.webp` 파일이 실제로 존재함
- 원본 파일이 이번 요청에 직접 사용된 파일임
- 다른 글이나 다른 작업에서 원본을 참조하지 않음

삭제 후 확인:
- 같은 이름의 원본 확장자 파일이 남아 있는지 확인한다.
- 최종 보고에 원본 삭제 여부를 명시한다.

## 6. 삽입 위치 규칙

[DO]
- 사용자가 지정한 삽입 위치를 우선한다.
- 지정 위치가 없으면 이미지 내용과 가장 직접적으로 연결되는 H2 섹션에 넣는다.
- 보통 H2 바로 아래 첫 줄 또는 해당 설명 문단 직후가 자연스럽다.
- 한 섹션에 이미 이미지가 있으면 다음 관련 섹션으로 분산한다.
- 이미지가 비교표, 단계표, 체크리스트 성격이면 해당 기준을 설명하는 문단 가까이에 둔다.
- 사용자가 캡션 반영을 명시 요청하면 본문 흐름을 해치지 않는 위치인지 먼저 확인한다.
- 이미지 삽입 위치를 정할 때도 기존 H2 순서, 문단 순서, related panel 구성을 유지한다.

[NOT]
- frontmatter 안에 이미지 마크업을 넣지 않는다.
- Quick Summary 안에 이미지를 넣지 않는다.
- Related panel 안에 이미지를 넣지 않는다.
- 하단 CTA 바로 안이나 CTA 직전에 이미지를 몰아넣지 않는다.
- 글 맨 위에 이미지가 본문 인트로보다 먼저 나오게 하지 않는다.
- 같은 이미지 파일을 같은 글 안에 두 번 이상 넣지 않는다.
- 캡션을 이미지마다 기계적으로 붙이지 않는다.
- OG 이미지 또는 썸네일 metadata를 본문 이미지 삽입 작업에 섞어서 처리하지 않는다.
- 이미지 삽입을 이유로 related card를 추가, 삭제, 재배열하지 않는다.
- 이미지 삽입을 이유로 H2/H3 제목이나 기존 본문 문장을 고치지 않는다.

MDX 문법:

```mdx
![짧고 구체적인 alt](/images/hub/[hub-slug]/[file-name-kr.webp])
```

## 7. Alt 작성 규칙

[DO]
- alt는 비워두지 않는다.
- alt는 실제 장면 설명을 우선한다.
- 검색 의도 키워드는 1개만 자연스럽게 포함할 수 있다.
- 한국어 파일은 한국어 alt, 영어 파일은 영어 alt를 쓴다.
- alt는 짧고 구체적으로 쓴다.
- 장소, 빛, 색감, 재질, 구도, 아이템, 비교 기준 중 1~2개를 드러낸다.
- 같은 글 안의 모든 alt를 같은 문장 구조로 반복하지 않는다.
- 여러 이미지가 있으면 alt마다 서로 다른 보조 키워드나 파생 표현을 우선 매칭한다.
- 영어 alt는 가능하면 125자 이내를 기본 상한선으로 본다.
- 한국어 alt도 한 문장 수준으로 유지한다.

[NOT]
- 제목 복붙 금지
- H2 복붙 금지
- 키워드 나열 금지
- 시적인 표현 금지
- 추상적인 감상 금지
- 같은 뜻 반복 금지
- 모든 이미지 alt에 같은 메인 키워드 반복 금지
- `A를 담은 사진`, `A가 보이는 장면`, `A 풍경` 같은 틀을 연속 사용 금지
- 감상문처럼 긴 alt 금지

추가 기준:
- 사용자가 준 alt가 있어도 SEO/접근성 기준에 맞지 않으면 보정한다.
- 허브 글 alt는 하위 글 메인 키워드를 뺏지 않는다.
- 하위 글 alt는 해당 글의 검색 의도와 장면에 맞춘다.
- 단순히 `거리에 서 있는 사람`처럼 건조하게 끝내지 말고, 실제로 보이는 질감이나 조건을 짧게 포함한다.
- Gemini가 만든 KO/EN alt는 언어, 장면, 키워드 반복 여부를 다시 검수한다.

예:
- 메인 키워드가 `명동 네온사인 야간 사진`이라면 alt를 모두 같은 키워드로 쓰지 않는다.
- 분산 예시: `명동 밤거리`, `서울 네온 포토존`, `비 온 뒤 반사`, `야간 스트릿 스냅`

## 7-A. 캡션, 썸네일, OG 처리 규칙

기본값:
- Gemini가 캡션을 만들었어도 MDX에는 기본 삽입하지 않는다.
- 썸네일 추천 또는 OG 이미지 프롬프트는 참고 정보로만 본다.
- 사용자가 명시적으로 요청한 경우에만 caption, thumbnail, OG metadata 반영을 별도 작업으로 검토한다.

캡션을 넣을 수 있는 경우:
- 사용자가 캡션 삽입을 명시적으로 요청했다.
- 캡션이 본문 문장을 반복하지 않고 이미지 이해를 돕는다.
- 캡션이 키워드 나열이 아니며 과장된 홍보 문구가 아니다.
- 기존 MDX 컴포넌트나 스타일이 캡션을 안정적으로 지원한다.

캡션을 넣지 않는 경우:
- 사용자가 이미지 본문 삽입만 요청했다.
- MDX에 캡션용 컴포넌트나 스타일이 명확하지 않다.
- 캡션이 alt나 주변 문장과 거의 같다.
- 캡션 때문에 본문 흐름이 광고처럼 보인다.

OG/썸네일 처리:
- OG 이미지는 본문 이미지 삽입과 별도 작업으로 본다.
- 사용자가 OG 이미지 반영을 요청하면 frontmatter 또는 metadata 구조를 먼저 확인한다.
- OG 이미지를 반영할 때도 실제 `.webp` 또는 프로젝트가 허용하는 이미지 파일 존재 여부를 확인한다.
- 본문 삽입용 이미지라고 해서 자동으로 OG 이미지로 지정하지 않는다.

## 8. 이미지 재사용 금지

[DO]
- 사용자가 현재 글 삽입을 위해 새로 준비한 이미지만 사용한다.
- 같은 허브 안에서도 허브 글과 하위 글은 서로 다른 이미지를 쓴다.
- 같은 이미지가 다른 파일명으로 복사된 경우도 재사용으로 본다.

[NOT]
- 기존 저장소 이미지 재사용 금지
- 이전 포스팅 이미지 재사용 금지
- 허브 글 이미지를 하위 글에 재사용 금지
- 하위 글 이미지를 다른 하위 글에 재사용 금지
- 같은 글 안에서 동일 이미지 파일을 2회 이상 사용 금지

AdSense 대응 관점:
- 스타일, 뷰티, 사진 주제에서는 고유 이미지나 자체 제작 비교 자료가 사용자 경험과 독창성 신호에 도움이 된다.
- 이미지가 있어도 alt 키워드 반복, 재사용 이미지, 본문과 무관한 장식 이미지는 품질 신호가 되지 않는다.

## 9. 작업 순서

1. 대상 URL 또는 slug 확인
2. 대상 KO/EN MDX 파일 확인
3. Gemini 결과물이 있으면 파일명, alt, 캡션, 썸네일/OG 추천을 초안으로 확인
4. 이미지 원본 파일 경로 확인
5. `-kr` / `-en` suffix 확인
6. `/images/...` 경로를 받았으면 `public/images/...` 실파일 확인
7. 원본 확장자 확인
8. 필요한 경우 `.webp` 생성
9. 실제 `.webp` 생성 여부 확인
10. 게시 경로 확정
11. 삽입 위치 확정
12. 본문 구조를 바꾸지 않고 이미지 마크업만 삽입 또는 기존 placeholder 교체
13. MDX에 `![alt](/images/...webp)` 삽입 또는 기존 placeholder 교체
14. alt 품질 점검
15. 캡션/OG 반영 요청이 있으면 별도 조건 확인
16. 원본 삭제 요청이 있으면 삭제 전 조건 확인 후 처리
17. MDX 참조 경로와 실제 파일 존재 여부 최종 검증
18. 최종 보고

강제 원칙:
- 순서를 바꾸지 않는다.
- 질문 없이 원본을 삭제하지 않는다.
- `.webp` 게시본이 없으면 MDX에 `.webp` 경로를 넣지 않는다.
- 이미지 삽입 후에는 최소한 해당 MDX의 문법과 참조 파일 존재를 확인한다.
- Gemini 결과물을 실제 파일 확인 없이 확정하지 않는다.
- 캡션/OG는 사용자가 명시 요청하지 않으면 반영하지 않는다.
- 사용자가 별도로 요청하지 않은 본문 구조 변경은 하지 않는다.

---

## 10. 최종 검증

이미지 삽입 후 반드시 확인한다.

- MDX에 남은 이미지 경로가 모두 `.webp`인가
- MDX의 `/images/...webp` 경로가 실제 `public/images/...webp` 파일과 대응하는가
- KO 글에는 KO alt, EN 글에는 EN alt를 썼는가
- alt가 비어 있지 않은가
- alt가 제목/H2 복붙이 아닌가
- 같은 글 안에서 alt 문장 구조가 반복되지 않는가
- 같은 이미지 파일을 중복 사용하지 않았는가
- Quick Summary, Related panel, 하단 CTA 안에 이미지를 넣지 않았는가
- 사용자가 원본 삭제를 요청한 경우에만 원본을 삭제했는가
- Gemini 파일명에서 `.webp`, slug, `-kr`/`-en` suffix를 보정했는가
- 캡션/OG/썸네일을 사용자가 요청하지 않았는데 임의로 반영하지 않았는가
- 이미지 삽입 요청 범위를 넘어 H2/H3, 본문 문단, related panel, CTA, 내부 링크 문구를 수정하지 않았는가

## 11. 최종 보고 항목

최종 보고에는 아래를 포함한다.

- 수정한 MDX 파일
- 삽입한 이미지 본문 경로
- 실제 게시 파일 경로
- `.webp` 변환 여부
- 원본 삭제 여부
- 반영한 alt
- Gemini 결과물 보정 여부
- 캡션/OG/썸네일 반영 여부
- MDX가 참조한 모든 `.webp` 파일 존재 여부
- 중복 이미지와 언어 혼합 alt가 없는지 여부
